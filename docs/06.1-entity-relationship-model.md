# 06.1 - Entity Relationship Model (ERD)

# Objetivo

Definir las entidades principales de Clufit y las relaciones entre ellas.

Este documento representa el modelo conceptual de la base de datos y sirve como referencia para el desarrollo del esquema SQL, las APIs y la lógica del producto.

# Relaciones Principales

## User

El usuario es la entidad principal del sistema.

Todas las entidades funcionales dependen directa o indirectamente de un usuario.

### Relaciones 1:N

- Goals
- Habits
- Workouts
- Recovery
- Nutrition
- Notifications
- Devices
- Recommendations
- Argus Insights
- Integrations
- Daily Snapshots

---

## Workout

```text
Workout
    │
    ▼
Workout Exercises
    │
    ▼
Exercises
```

Una rutina contiene múltiples ejercicios.

Un ejercicio puede pertenecer a múltiples rutinas.

Relación **N:M** mediante `WorkoutExercises`.

---

## Workout Sessions

```text
Workout
    │
    ▼
Workout Session
```

Cada ejecución de una rutina genera un historial independiente.

Las sesiones nunca se sobrescriben.

Esto permite medir evolución, rendimiento y progresión.

---

## Habits

```text
Habit
    │
    ▼
Habit Logs
```

Cada hábito genera registros diarios.

Estos registros permiten calcular:

- Rachas
- Consistencia
- Porcentaje de cumplimiento
- Discipline Score

---

## Goals

Cada objetivo pertenece a un usuario.

En futuras versiones podrán existir objetivos compartidos mediante el Sistema de Sincronización.

---

## Synchronization

```text
User
    │
    ▼
Synchronization
    │
    ▼
Partner
```

Representa el vínculo entre dos usuarios.

No modifica la entidad `Users`.

Permite activar funcionalidades colaborativas sin afectar la experiencia individual.

---

## Challenges

```text
Synchronization
        │
        ▼
Challenge
        │
        ▼
Challenge Participants
```

Todo reto pertenece a una sincronización.

Cada reto puede tener múltiples participantes.

---

## Argus

Argus no almacena información propia del usuario.

Consume información desde todos los módulos del sistema.

Genera únicamente:

- Insights
- Recomendaciones
- Scores
- Explicaciones

---

## Notifications

Todas las notificaciones nacen a partir de eventos del sistema.

Posibles orígenes:

- Dashboard
- Objetivos
- Disciplina
- Productividad
- Fitness
- Recuperación
- Nutrición
- Argus
- Retos
- Sincronización

---

# Entidades Auxiliares

## Exercise Categories

```text
Exercise Categories
        │
        ▼
Exercises
```

Permite clasificar ejercicios.

Ejemplo:

- Pecho
- Espalda
- Piernas
- Hombros
- Brazos

---

## Muscle Groups

```text
Muscle Groups
        │
        ▼
Exercises
```

Normaliza la información muscular y evita duplicación.

---

## Notification Templates

Centraliza todos los modelos de notificación.

Ejemplos:

- Entrenamiento
- Hidratación
- Argus
- Recordatorios
- Retos
- Sincronización

---

## Challenge Types

Define los distintos tipos de retos.

Ejemplos:

- 10.000 pasos
- Entrenamientos
- Agua
- Sueño
- Cardio
- Peso levantado
- Tiempo sin procrastinación

---

## Score History

Historial de evolución de todos los indicadores principales.

Incluye:

- Overall Score
- Discipline Score
- Productivity Score
- Recovery Score
- Procrastination Score
- Fitness Score
- Nutrition Score
- Notification Score

Permite construir gráficos históricos y detectar tendencias.

---

# Daily Snapshots

## Objetivo

Generar un resumen consolidado del estado diario del usuario.

Cada jornada finalizada produce un único registro que resume toda la actividad.

Esta entidad evita recalcular información histórica constantemente y facilita el trabajo de Argus.

### Campos sugeridos

- date
- overall_score
- discipline_score
- productivity_score
- recovery_score
- procrastination_score
- fitness_score
- nutrition_score
- notification_score
- argus_summary

---

# Beneficios

- Dashboards más rápidos.
- Consultas históricas optimizadas.
- Menor carga sobre la base de datos.
- Mejor rendimiento para Argus.
- Base para reportes y analítica.

---

# Escalabilidad

El modelo está preparado para incorporar futuras entidades como:

- Communities
- Achievements
- Badges
- CMS
- Blog
- Marketplace
- Eventos
- Rankings

Sin modificar las relaciones principales del sistema.

---

# Decisions

## Decision 001

El usuario es la entidad raíz del sistema.

---

## Decision 002

La sincronización se implementa mediante relaciones independientes entre usuarios.

---

## Decision 003

Argus únicamente genera información derivada; nunca modifica los datos originales.

---

## Decision 004

Todo dato histórico debe conservarse para permitir análisis de evolución.

---

## Decision 005

La entidad `Daily Snapshots` será la principal fuente para dashboards, gráficos e inteligencia artificial histórica.
